## 0. Короткий вердикт

Игра **технически живая**, но **не интересная**. Сейчас это не симулятор
жизни, а диорама с ресурсными числами: мир красиво выглядит на скриншоте,
но в него неприятно вглядываться и нечем в нём заниматься.

Главная проблема не в количестве контента. Главная проблема в том, что
**существо не является субъектом**: у него нет видимых целей, действий,
реакций, работы, эмоций и истории. Оно бегает по случайным точкам, а
поселение абстрактно строит здания без строителей. Игрок не может
привязаться к болванчику, повлиять на него точечно или увидеть последствия
своего вмешательства.

Вторая критическая проблема — **фризы на любом изменении ландшафта**.
Она блокирует главный цикл «бог трогает мир» и делает самые зрелищные
действия (бомба, метеорит, ядерный удар) самыми неприятными по ощущениям.

**Просьба:** не наращивать контент, пока не закрыты P0-пункты 1–5 и 11.
Иначе новый контент унаследует ту же проблему: его будет не с кем связать
и не на что смотреть.

## 1. Как воспроизводилось

1. Запустить `build/Aetheria.cmd`.
2. Создать мир 256×256, seed 12345, 6 племён, песочница.
3. 3–5 минут наблюдения на 1×, затем 2–3 минуты на 20×.
4. Выбрать поселение, включить «Осмотр», кликнуть по существам.
5. Применить кисть «Поднять»/«Опустить» радиусом 16–32, затем 32.
6. Применить молнию, бомбу, метеорит, ядерный удар.
7. Повторить на 512×512.
8. Сохранить/загрузить, проверить поведение после загрузки.

Наблюдения стабильны на разных seed'ах; проблема не в одном «неудачном»
мире, а в самой модели поведения.

## 2. Почему игра ощущается неинтересной

Сейчас цикл такой:

```
игрок смотрит на мир → кидает катастрофу → видит цифры/частицы
→ ничего не меняется в историях существ → повторять
```

В интересном god sim цикл должен быть таким:

```
игрок замечает существо/поселение → понимает его цель/проблему
→ вмешивается точечно → видит немедленную реакцию
→ наблюдает последствия в истории и отношениях
→ хочет проверить ещё одну гипотезу
```

В текущей версии **нет звена «реакция»**. Существо не показывает, что ему
больно, страшно, радостно или голодно. Поселение не показывает, кто и что
строит. Война — это медленное перетаскивание точек по карте. Игрок не
формирует привязанность и не видит причинно-следственных связей.

Ниже — 13 конкретных претензий с приоритетами, ссылками на код и
критериями приёмки.

## 3. Findings

### 3.1. P0/S1 — Болванчики бегают вокруг костра и медленно ползут на войну

**Симптом.** В мирное время существа хаотично меняют цель между случайным
зданием и случайной точкой в радиусе территории. Во время войны они
физически идут к чужому центру, но это выглядит как медленное
перетаскивание точек, без строя, припасов, привалов, разведки и тактики.

**Где в коде.**
- `scripts/core/sim.gd:1142` `_assign_targets()` — выбор цели:
  - 62% — случайное здание;
  - иначе — случайная точка в радиусе;
  - воин — `target = enemy.center`.
- `scripts/game.gd:401` `_move_agents()` — движение к точке с постоянной
  скоростью, без проверки препятствий, строя, усталости и роли.
- `scripts/core/sim.gd:590` `_siege_tick()` — бой считается абстрактно,
  когда воины оказались в радиусе 20/16 клеток; визуально это не бой.

**Почему не весело.** Игрок не может прочитать намерение. Нет сцены:
«охотник крадётся», «отряд строится», «посол идёт», «ребёнок убегает».
Нет ставки: исход войны не зависит от того, что игрок видит.

**Что просим.**
1. Ввести **AgentAction** (см. Приложение A): действие, цель, длительность,
   прогресс, анимация, эффект. Движение — только следствие действия.
2. Заменить случайные цели на **utility AI**: голод → еда, стройка →
   стройплощадка, тревога → укрытие, война → сбор отряда, патруль и т.д.
3. Для войны: точка сбора, построение, марш колонной, привал, разведка,
   осада, отступление. Даже 3–4 состояния дадут сцену.
4. Запретить «телепорт-цели»: агент не должен мгновенно менять цель без
   причины; смена — через прерывание с приоритетом.

**Критерии приёмки.**
- За 5 минут наблюдения одно существо совершает ≥5 различных видимых
  действий.
- Военный отряд показывает минимум 3 фазы: сбор → марш → осада.
- Нет бесконечного «орбитального» бега вокруг костра без действия.

### 3.2. P0/S1 — Все существа на одно лицо

**Симптом.** Все люди/эльфы/орки — один и тот же низкополигональный меш с
разным оттенком. Нет лиц, причёсок, телосложения, одежды, возраста,
увечий, аксессуаров. Игрок не различает даже лидера и ребёнка, кроме
цвета и размера.

**Где в коде.**
- `scripts/world/creature_view.gd:23` — один `MeshKit.person_mesh()` на
  всех.
- `scripts/world/creature_view.gd:92` `rebuild_slots()` и
  `_agent_color()` — единственная вариация: цвет расы, лидер/воин,
  светлее/темнее.
- `scripts/core/mesh_kit.gd:258` `person_mesh()` — один фиксированный
  набор цилиндров и сфер; без вариантов головы, тела, одежды.

**Почему не весело.** Игрок не может выбрать «любимого» болванчика,
запомнить его, пожалеть, наказать, наградить. Нет социальной дистанции
между массой и личностью.

**Что просим.**
1. 6–10 визуальных вариантов тела/головы/причёски + 8–12 аксессуаров
   (шляпа, борода, капюшон, фартук, молот, посох, корона, шрам).
2. Возрастные силуэты: ребёнок, взрослый, старик; беременность; раненый.
3. Идентичность в инспекторе: имя, прозвище, лицо/иконка, роль, перки,
   настроение, семья. Уникальный цвет/метка для лидера и избранного.
4. Дешёвая реализация: MultiMesh + per-instance custom data/atlas или
   несколько MultiMesh-слоёв; не создавать 1000 Skeleton3D.
5. Эмоции на лице/над головой: иконка голода, страха, гнева, радости.

**Критерии приёмки.**
- На экране одновременно видны минимум 8 явно разных силуэтов.
- Игрок может узнать ранее выбранного болванчика без подписи.
- Лидер визуально отличим от рядового без наведения.

### 3.3. P0/S1 — Нет анимаций, работы, молотка и иерархии строителей

**Симптом.** Существа скользят по земле без шага, не машут руками, не
работают. Стройка — абстрактный счётчик: здание появляется, когда
`progress >= days`, без строителей, инструментов, лесов и прораба.

**Где в коде.**
- `scripts/core/sim.gd:360` `_construction_tick()`:
  `progress += 1`, затем `add_building`. Нет списка строителей, нет
  привязки к конкретным агентам.
- `scripts/core/sim.gd:445` `_find_building_spot()` — только выбор точки.
- `scripts/world/settlement_view.gd` — стройплощадка показывает
  приблизительный прогресс, но не людей.
- `scripts/core/sim.gd:1159` — роли (builder) присваиваются, но не
  используются для стройки.
- `scripts/core/mesh_kit.gd` — нет молотка/инструмента как отдельного
  визуального слоя.

**Почему не весело.** Стройка — главный видимый процесс роста поселения,
но игрок не видит труда. Нет истории «этот дом построил этот болванчик».

**Что просим.**
1. У стройки: 1–3 слота строителей, прораб/архитектор, очередь задач.
2. Строитель идёт к площадке, играет анимацию удара молотком, несёт
   материал, делает вклад в прогресс; при уходе прогресс замедляется.
3. Визуал: леса, штабель брёвен/камня, молоток, пыль, звук.
4. Иерархия: лидер → прораб → строители → подсобники; учитывать
   лидерство/навык craft; ошибки/травмы/срывы.
5. После завершения — событие в хронику с именами участников.

**Критерии приёмки.**
- При строительстве дома на площадке видны ≥1 строитель и анимация удара.
- Прогресс здания заметно замедляется, если строителей нет.
- В инспекторе здания видно, кто строит и сколько осталось.

### 3.4. P0/S1 — Нет радости и горя

**Симптом.** `mood` и `sanity` — числа в инспекторе. Смерть, пожар,
голод, чудо, рождение не вызывают видимых реакций. Нет слёз, смеха,
паники, праздника, траура.

**Где в коде.**
- `scripts/core/sim.gd:213` `_agents_daily()` — mood плавно тянется к
  счастью поселения, но не порождает действий/анимаций.
- `scripts/world/fx.gd` — есть VFX катастроф/благословений, но не
  эмоциональные реакции существ.
- HUD показывает потребности, но не эмоциональные события.

**Что просим.**
1. Ввести `emotion` (neutral/happy/sad/angry/afraid/hungry/proud/grieving)
   и `emotion_reason`.
2. Реакции: поза, скорость, иконка, звук, реплика, поведение
   (бежать, плакать у могилы, праздновать у костра, прятаться в дом).
3. События: рождение, смерть близкого, пожар, чудо, голод, победа,
   разрушение дома, назначение лидером.
4. Эмоции должны влиять на решения: испуганный бежит, убитый горем
   хуже работает, вдохновлённый — лучше.

**Критерии приёмки.**
- Минимум 6 эмоций с видимой реакцией.
- После смерти лидера виден траур/паника, а не только минус в хронике.
- Игрок может вызвать эмоцию точечно (благословение/проклятие) и увидеть
  реакцию в течение 1–2 секунд.

### 3.5. P0/S1 — Нужен примитивный, но настоящий AI, а не «ради галочки»

**Требуемый пример поведения:**
> Болванчик видит животное → идёт за ним → атакует → убивает →
> тащит тушу к дому → разделывает/складывает → выходит с едой →
> ест → доволен. Если еды нет — ищет траву или выращивает её на ферме.

Сейчас этого нет: есть потребности и случайные цели, но нет цепочки
«восприятие → решение → действие → предмет → последствие».

**Где в коде.**
- `scripts/core/sim.gd:213` — потребности уменьшаются, но еда берётся
  абстрактно из `s.resources["food"]`.
- `scripts/core/sim.gd:1142` — цель «seekFood» ведёт к зданию, но
  анимации еды/предмета нет.
- `scripts/core/agent.gd` — нет полей действия, инвентаря, цели-объекта,
  таймера действия.

**Что просим.**
1. **Utility AI / GOAP-lite** (Приложение A):
   - голод, жажда, усталость, страх, социальная потребность, работа;
   - выбор действия по score = utility × personality × urgency;
   - действия: `hunt`, `haul`, `butcher`, `eat`, `drink`, `sleep`,
     `work`, `build`, `socialize`, `pray`, `patrol`, `flee`.
2. Инвентарь/переносимый предмет: туша, еда, бревно, камень, инструмент.
3. Охота: обнаружение → преследование → удар → смерть животного →
   перенос туши → склад/дом → еда.
4. Ферма: посадка/рост/сбор; видимые грядки; голодный может сорвать
   траву, если есть.
5. Отладка: debug-панель действия/цели/utility для выбранного агента.

**Критерии приёмки.**
- Сценарий «охота → туша → еда → доволен» воспроизводится в 5 минутах.
- Голодный агент без еды идёт к траве/ферме, а не стоит.
- В инспекторе видно текущее действие, цель и причину.

### 3.6. P1/S2 — Мир из вечных холмов и вертикальных пиков

**Симптом.** Карта читается как бесконечная пересечённая местность;
деревни стоят на склонах, иногда на острых пиках; нет равнин, долин,
побережий, террас и понятных ориентиров. Один и тот же «шумный» рельеф
на всей карте.

**Где в коде.**
- `scripts/core/world.gd:215` `_generate_heights()` — FBM + ridged шум,
  `ridge^2.1`, mountain mask; после — лёгкое сглаживание.
- `scripts/core/world.gd:291` — 3 прохода усреднения, но без
  гидравлической эрозии/террас/долин.
- `scripts/core/world.gd:816` `find_settlement_sites()` — отсекает
  `mountains`, но не проверяет уклон на площади застройки; `rough > 0.13`
  — слишком мягкий критерий.
- Высота 86 units делает даже небольшой перепад визуально крутым.

**Почему не весело.** Нельзя прочитать карту: где безопасно, где дорога,
где ферма, где перевал. Деревня на вертикальной горе выглядит абсурдно.

**Что просим.**
1. Генерация: крупные **равнинные бассейны**, долины рек, террасы,
   поймы, береговые линии; горы — ограниченные хребты, а не весь рельеф.
2. Эрозия: гидравлическая/термальная, 2–3 прохода; убрать одиночные
   пики; ограничить максимальный уклон.
3. Выбор места: проверять уклон на footprint 5×5/7×7, ровность,
   доступ к воде, ресурсам, соседям; запрещать уклон >10–15°.
4. Визуальные ориентиры: реки, дороги, перевалы, руины, леса, скалы.
5. Пресеты: «равнины», «архипелаг», «горная долина», «пустошь».

**Критерии приёмки.**
- ≥80% поселений стоят на участке с уклоном <10°.
- На карте есть минимум 2 крупные равнины/долины и читаемые ориентиры.
- Нет поселений на пиках и одиночных иглах.

### 3.7. P1/S2 — Мало интерактивности с миром

**Симптом.** 46 сил есть, но большинство — «нажал → частицы → цифры».
Нельзя точечно пожалеть/наградить болванчика, поднять его, дать имя,
заставить работать, спасти, наказать. Нет быстрой обратной связи
«я сделал — он отреагировал».

**Где в коде.**
- `scripts/game.gd:633` `_apply_tool()` — основной набор сил.
- HUD `inspect_agent()`/`inspect_settlement()` показывает карточку, но
  действия ограничены «в центр/следить».
- `data/powers.json` — 46 сил, но нет индивидуальных действий над
  существом, кроме area-эффектов.

**Что просим.**
1. В инспекторе существа: «Благословить», «Проклясть», «Исцелить»,
   «Дать перк», «Сделать бессмертным», «Дать имя», «Позвать»,
   «Напугать», «Наградить».
2. В инспекторе поселения: «Дать ресурсы», «Дать технологию»,
   «Назначить лидера», «Послать пророка», «Объявить войну/мир»,
   «Построить дорогу» (после п.12).
3. Немедленная реакция: анимация/эмоция/звук/иконка в течение
   1–2 секунд.
4. «Избранное» существо: закреплённая карточка, уведомления о событиях,
   быстрый переход.
5. «Пакости» бога: точечные, с последствиями, а не только area-урон.

**Критерии приёмки.**
- 10 точечных действий над существом с видимой реакцией.
- Игрок может выбрать любимого болванчика и получать уведомления о нём.
- Любое действие бога имеет feedback в мире, а не только в цифрах.

### 3.8. P1/S2 — Нельзя добавить в мир каждый отдельный вид

**Симптом.** Есть «племя» и «животное» (случайный вид), но нельзя
выбрать конкретную расу, пол, возраст, животное, монстра. Нет меню
«создать существо».

**Где в коде.**
- `data/powers.json`: `tribe`, `animal`.
- `scripts/core/sim.gd:1619` `spawn_tribe()` — раса выбирается по биому.
- `scripts/core/sim.gd:1096` `_spawn_animal()` — вид передаётся, но UI
  не даёт выбрать.
- Нет UI-панели параметров спавна.

**Что просим.**
1. Инструмент «Создать существо»: раса → пол → возраст → уровень →
   перки → поселение/одиночка.
2. Инструмент «Создать животное»: список всех видов, пол, возраст,
   домашнее/дикое.
3. Предпросмотр модели/иконки и точки постановки.
4. Спавн не должен ломать баланс: стоимость эссенции/лимит.
5. Все виды из `data/races.json`, `data/animals.json` доступны.

**Критерии приёмки.**
- В меню можно создать каждую расу и каждый вид животного.
- Созданное существо имеет выбранные пол/возраст/перки.
- Спавн виден в мире и в инспекторе.

### 3.9. P1/S2 — Нельзя выдавать перки, навыки и бессмертие

**Симптом.** Перки и статы есть в данных, но игрок не может их менять.
Бессмертия нет вовсе: `maxAge` и смерть от старости жёстко в цикле.

**Где в коде.**
- `scripts/core/agent.gd` — поля `perks`, `skills`, `level`, `maxAge`,
  но нет `immortal`.
- `scripts/core/sim.gd:267` — возрастная смерть.
- HUD `inspect_agent()` — только просмотр.

**Что просим.**
1. God-edit режим в инспекторе: добавить/убрать перк, поднять навык,
   уровень, изменить удачу/харизму.
2. Флаг `immortal` (не стареет, но может быть убит физически;
   отдельный флаг `unkillable` — опционально).
3. Визуальные маркеры: аура, иконка, цвет имени.
4. Сохранение/загрузка флагов и перков.
5. Ограничения песочницы/челленджа (в обычной игре — стоимость,
   в песочнице — бесплатно).

**Критерии приёмки.**
- Можно выдать/снять перк и увидеть эффект в статах.
- Бессмертный не умирает от старости; в инспекторе виден статус.
- После save/load изменения сохраняются.

### 3.10. P1/S2 — Старт с готовых деревень вместо «первородных»

**Симптом.** На старте уже стоят хижины и farms, а племя появляется
готовым. Нет ощущения зарождения цивилизации. Нет «первородных» существ
с высокими статами, которые сами создают лагерь.

**Где в коде.**
- `scripts/core/sim.gd:73` `populate()`:
  - `s.add_building("hut", ...)`;
  - `s.add_building("farm", ...)`;
  - 9–13 взрослых + 2–4 ребёнка.
- `scripts/core/sim.gd:1619` `spawn_tribe()` — тоже сразу hut + farm.
- `scripts/core/sim.gd:83` комментарий «стартовые постройки».

**Что просим.**
1. Новый режим/опция **Genesis**:
   - на карте нет поселений;
   - 3–7 групп «первородных» (макс. статы/перки, уникальные имена);

3. В хронике: «Первые костры», «Первое жилище», «Первый ребёнок».
4. Первородные должны заметно отличаться визуально/статами.

**Критерии приёмки.**
- В Genesis на старте нет готовых зданий (кроме костра).
- Через 10–15 минут видны первые постройки, созданные AI.

### 3.11. P0/S1 — Сильные фризы при любом изменении ландшафта

**Симптом.** Кисть, молния, бомба, метеорит, ядерный удар вызывают
резкие просадки/замирания. На 512×512 — особенно. Это самый
раздражающий технический дефект: он бьёт по главному действию игрока.

**Причины в коде (подтверждено чтением).**
1. `WorldModel.raise_area()` и `water_area()` испускают **два** сигнала:
   `terrain_changed` и `biomes_changed`.
2. `TerrainView` подписан на оба:
   - `_on_terrain_changed()` → `rebuild_rect()`;
   - `_on_biomes_changed()` → **снова** `rebuild_rect()`.
   То есть один мазок пересобирает одни и те же чанки дважды.
3. `NatureView` на оба сигнала делает `mark_dirty()` и через 0.7 с
   вызывает **полный** `rebuild()`: перебор всех клеток карты,
   пересоздание всех MultiMesh и всех мешей деревьев/камней.
   На 512² это ~262k клеток.
4. `TerrainView._build_minimap()` при dirty перерисовывает **всю**
   карту по пикселям. Вызывается из игрового цикла часто, пока кисть
   активна.
5. `sim.nuke()`/`meteor()` последовательно вызывают несколько
   `raise_area`/`paint_biome`/`ignite`, каждый с собственными сигналами
   и пересборками.
6. `TerrainView.rebuild_rect()` пересобирает и terrain, и water чанки
   для любого изменения, даже если вода не менялась.
7. Нет бюджетов/очередей: работы выполняются синхронно в кадре,
   нет «не более N чанков за кадр».

**Что просим (P0, до контента).**
1. **Один коалесцированный сигнал**: `world_edited(rect, flags)` раз в
   кадр/тик; `terrain_changed`/`biomes_changed` — только внутренние,
   без двойной подписки.
2. **Очередь грязных чанков**: пересобирать terrain/water не более
   1–2 чанков за кадр; при кисти — только реально изменённые.
3. **Чанковый NatureView**: 32×32 чанки флоры, отдельные MultiMesh на
   чанк; обновлять только затронутые; кэшировать меши; не сканировать
   всю карту.
4. **Инкрементальная миникарта**: обновлять только прямоугольник
   изменений; троттлинг 4–10 Гц; `ImageTexture.update` не на каждый
   кадр.
5. **Разделить флаги**: `height_dirty`, `water_dirty`, `biome_dirty`,
   `veg_dirty`; не пересобирать воду при изменении только высоты.
6. **Отложенные VFX**: сначала данные, затем эффекты; ядерный удар
   не должен 5 раз пересобирать мир.
7. **Профилировать**: p50/p95/p99 frame time, счётчик rebuilds,
   время `rebuild_rect`, `NatureView.rebuild`, `_build_minimap`.

**Критерии приёмки.**
- Непрерывный мазок кистью радиусом 32 на 512×512: нет кадров >33 мс,
  средний FPS ≥60.
- Бомба/метеорит/ядерный удар: нет фриза >50 мс, визуальный эффект
  не задерживается.
- `NatureView.rebuild()` не вызывается на каждый мазок; только
  изменённые чанки.
- В логе профайлера видно, что пересборка не дублируется.

### 3.12. P1/S2 — Нет дорог между поселениями

**Симптом.** Поселения торгуют/воюют абстрактно, но на карте нет дорог.
Даже если города «знают» друг о друге, связь не видна и не влияет на
движение.

**Где в коде.**
- `SettlementData` не имеет графа дорог/известных поселений.
- `_move_agents()` ведёт агента по прямой.
- `_diplomacy_daily()`/`_yearly()` меняют отношения без визуальной связи.
- Нет инструмента/постройки «дорога».

**Что просим.**
1. `known_settlements` (кто кого обнаружил: разведка, торговля,
   граница, война).
2. Дороги — граф/сегменты по клеткам; строятся, если поселения знают
   друг о друге и есть ресурсы/рабочие.
3. Строительство: бригада выходит, прокладывает сегменты, дорога
   видна на карте; повреждение/ремонт.
4. Эффекты: скорость караванов/армий, торговля, налоги, дипломатия.
5. Инструмент бога «Дорога» (опционально) для песочницы.

**Критерии приёмки.**
- Два поселения после контакта строят видимую дорогу.
- Агенты/караваны используют дорогу и движутся быстрее.
- Дорога сохраняется/загружается и влияет на торговлю.

### 3.13. P2/S2 — Нет исследователей-учёных и разведки

**Симптом.** Нет групп, которые выходят из поселения, ищут место,
основывают лагерь или вступают в контакт. Поселения растут/воюют
телепортом абстрактных решений.

**Где в коде.**
- `scripts/core/sim.gd:473` `_research_tick()` — наука только в
  поселении, без экспедиций.
- `scripts/core/sim.gd:952` `_expand_colony()` — колония появляется
  без группы, идущей по карте.
- `_diplomacy_daily()`/`_yearly()` — контакт без посла/разведчика.

**Что просим.**
1. `Expedition`/`ScoutParty`: 2–4 агента, роль scholar/scout, припасы,
   цель, маршрут, возврат.
2. Разведка: обследовать область, открыть `known_settlements`,
   оценить участок (ровность, вода, ресурсы, безопасность).
3. Если найдено хорошее место — основать лагерь (с группой), если
   встречено поселение — дипломатический контакт/обмен/шпионаж.
4. Визуал: отряд идёт, несёт флаг/сумки, разбивает лагерь, возвращается.
5. В хронике: «Экспедиция X отправилась…», «Найден перевал…»,
   «Контакт с Y».
6. Ограничения: риск гибели, голод, потеря припасов, возврат.

**Критерии приёмки.**
- Видимая группа выходит из поселения и возвращается.
- Найденный участок превращается в лагерь или контакт с поселением.
- Событие в хронике иrelations/known обновляются.

## 4. Что это значит для продукта

### 4.1. Сначала — «живой болванчик», потом — контент

Сейчас любая новая раса/животное/здание будет ощущаться как ещё одна
текстура на той же диораме. Нужен **вертикальный срез агента**:

```
восприятие → потребность → utility-решение → действие
→ анимация/предмет → эффект в мире → эмоция → событие в хронике
```

Если этот цикл заработает на одном человеке, его можно масштабировать
на 1000. Без него масштабирование только усилит «муравейник без смысла».

### 4.2. Приоритеты

| Приоритет | Пункты | Почему |

## 6. Что уже работает и не надо ломать

- Процедурная генерация и низкополигональный стиль.

- Экономика/технологии/эпохи/войны как скелет.

- Атмосфера: ночь, дождь, молния, ядерный гриб, смерч.

скелет не оживлён**. Нужно вложиться в поведение и обратную связь,
а не в ещё один биом.

## 7. Приложение A — предложение по AgentAction/utility AI

```gdscript
class_name AgentAction
extends RefCounted

var id: String                 # "hunt", "haul", "eat", "build", "pray"
var target_pos: Vector2
var target_id: int             # animal/building/agent
var duration: float            # секунды/игровые часы
var progress: float
var utility: float
var animation: String          # "walk", "chop", "carry", "eat"
var interruptible: bool = true
var on_complete: Callable
```

```text
every decision_tick (0.5–2 s or on need threshold):
  for each action in available_actions(agent):
      score = base_utility(action)
            * personality_mod(agent, action)
            * urgency(agent, action)
            * distance_mod(agent, target)
      pick max(score)
  if new_action.score > current.score * 1.15:
      interrupt_current()
      start(new_action)
```

Примеры действий:

- `hunt(animal_id)`: perceive → chase → attack → kill → `carry(carcass)`.
- `haul(item, stockpile)`: walk → pick up → carry → deposit.
- `eat(food_item)`: go to food → take → sit → eat → mood+.
- `build(site_id)`: go to site → hammer loop → progress → complete.
- `socialize(agent_id)`: go to agent → talk → mood+ → relationship+.
- `flee(threat_pos)`: run away → hide → fear decay.
- `explore(region)`: scout → discover → return / found camp.

**Важно:** анимация и предмет — не косметика, а доказательство действия.
Игрок должен видеть, что болванчик **делает**, а не только куда идёт.

## 9. Приложение C — сценарий приёмки «живой болванчик»

1. Запустить Genesis, 1 племя, 8 существ.
2. Выбрать охотника, включить debug-панель.

9. Отправить экспедицию; она находит место/поселение; событие.

## 10. Итоговая просьба

Просим считать пункты **1–5 и 11** блокерами релиза. Это не «полировка»,
это фундамент ощущения игры. Пункты 6–10, 12–13 — следующий слой,
без которого мир остаётся плоским.

Игра уже имеет хороший технический каркас. Ей не хватает **жизни в
болванчиках и отзывчивости мира**. Если вложиться в это сейчас, тот же
контент заиграет в разы сильнее. Если продолжать добавлять биомы и
кнопки — получится ещё более красивая, но всё такая же неинтересная
диорама.
