# Security policy

## Секреты и учётные данные

- В репозиторий **запрещено** коммитить токены GitHub, пароли, `.env`, SSH-ключи,
  cookies, файлы `docs/GITHUB_DATA.md` и любые пользовательские данные.
- `.gitignore` блокирует известные опасные имена. Это не заменяет бдительность:
  перед коммитом проверяйте `git diff --cached`.
- Если секрет случайно попал в Git:
  1. Немедленно отзовите токен/ключ у провайдера.
  2. Очистите историю (`git filter-repo` или BFG).
  3. Сделайте force-push **только** после согласования с правообладателем.
  4. Проверьте форки, кэши CI и артефакты.

## Проверка перед публикацией

```powershell
# ищем признаки секретов; шаблон намеренно не содержит реальных префиксов
git grep --cached -n -E "(token|secret|password|credential)[[:space:]]*[:=]"
git status --ignored
```

## Сообщение об уязвимости

Не создавайте публичный issue с эксплойтом. Передайте описание приватно
правообладателю проекта. Укажите версию, шаги воспроизведения и влияние.

## Правило минимальных прав

Для автоматизации используйте отдельный fine-grained token с доступом только
к нужному репозиторию и только к `Contents: Read and write`. Не используйте
личный classic-token с полными правами.
